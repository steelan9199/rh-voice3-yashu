## 一、参考音频（clone / director / dialogue4 共用）

| 要求 | 官方原话 | 踩了会怎样 |
|---|---|---|
| 干净、**不循环** | clean, **non-looping** speech with minimal background noise | 循环/重复素材 → 模型学进循环感，输出节奏发死 |
| 单人 | 一个说话人 | 多人 → 音色被平均成四不像 |
| 配**完整**文稿 | `--ref-text` 匹配**完整口语内容**，音频里的重复也要写进去 | 错字、漏词、漏重复 → 相似度和韵律一起掉 |

**时长：60 s 是节点层硬上限，不是模型层的真天花板。** 两层要分开说，别混成一句：

- **节点包 README 原话**："keep them under ~20 s (hard max 60 s)"——20 s 是推荐值，60 s 是硬上限（节点源码里对应的常量与理由见 `breezetts2-dialogue-SKILL.md` 落地校正 §5）。
- **模型层**：真正吃紧的是 `MAX_SEQ_LEN = 2048`。文本 token + 参考音频 token + 输出 token **共用**这 2048，音频按 12.5 token/秒计。20 s 参考 ≈ 250 token，60 s ≈ 750 token——参考越长，留给台词的空间越小，超了就是截断或崩。

所以：常用 **10–20 s**；超过 20 s 用 `--trim` 截；**不要超过 60 s**（节点层会拒），也不要拿长素材去赌台词长度。

`--ref-audio` 和 `--ref-text` 官方是**硬成对**（`infer.py` 里缺一个直接 raise）。RH 上分两条图走：默认那条由 `#60 Apply Whisper` 自动补文稿、改不了；带参考文稿那条（加 `--ref-text`）把 `#56.reference_text` 直接接到手写文本节点，**图里没有 Whisper**，文稿一个字都由你定。

参考音频槽位只认上传接口返回的 `fileName`（`openapi/xxx.flac`），不认本地路径、也不认下载 URL。脚本自动上传，同内容 18 小时内不重传（缓存运行时写在技能目录下，按「账号指纹 + 内容 sha」分键，换账号不会误用别人的文件）。

要复用一个已有的 `fileName`（写进批量配置、发给同事、或换台机器不想重传），单独跑 `upload`：它会打印 `openapi/xxx.mp3`，之后直接 `--ref openapi/xxx.mp3`，脚本会跳过上传并原样当文件名提交。

**路径规则**：所有**输入**（`--ref` / `--cast` / `--in` / `--text-file`）的相对路径先按当前目录找，找不到退回技能根目录——所以 cast 里写 `assets/refs/...`，从任何 cwd 调都能解析（2026-10-30 从 `D:\` 用绝对路径调 cast 验过）。**输出目录不回退**，仍按 cwd 解析，一律显式给绝对路径。

## 二、转写有错字怎么办

默认那条图的文稿是 Whisper 转的，**错字不会报错，只会悄悄掉质量**。实测：「你别装作不记得」→ 转成「你别装作不计的」（jìde 同音），这句文稿就带错进模型。

三条路：

| 做法 | 成本 | 效果 |
|---|---|---|
| 忍 | 0 | 一字之差会让整条轨道重走，时长可差 33%，不是局部小抖动 |
| 先 `stt` 校对，再 `--ref-text` 喂回去 | 多跑一次转写（也扣币） | 错字归零；顺带能看出漏词、漏重复 |
| 换一段更干净的素材 | 0（但要重录） | 从源头解决，最稳 |

**敏感度**：一字之差是整轨重走，不是局部抖动——所以别拿单条对单条下结论，同 seed 也不保证复现（数字见 `实测数据.md` §五）。

校对不用逐字核，只扫同音字就够：记得/计的、在/再、的/地、他/她、做/作。**扫的顺序：人名 > 数字 > 句尾语气词**（前两类错了最伤，最后一类错了听不出来但会让音色偏）。

```bash
node scripts/rhv.mjs stt --ref 参考.mp3 --out ./tmp-voice      # 出参考.txt，全文也打到屏幕
# 人眼改完 txt，再喂回去：
node scripts/rhv.mjs clone --text "台词" --ref 参考.mp3 --ref-text-file ./tmp-voice/参考.txt
```

## 三、台词里能插语气事件（官方一等能力，别漏）

想让某处有笑声、叹气、咳嗽、清嗓子，**直接写进台词**，别写进指令：

| 语言 | 写法 | 官方词表 |
|---|---|---|
| 中文 | 方括号 | `[笑]` `[叹气]` `[咳嗽]` `[清嗓子]` |
| 英文 | 圆括号 | `(laugh)` `(sigh)` `(cough)` `(clears throat)` |

- **括号里的内容不朗读**，是控制信号——`[叹气]` 不会念出「叹气」两个字。
- **括号形状必须跟语言配对**。英文台词写成 `[sigh]` 不生效，只是两个没用的符号；反之中文台词写 `(叹气)` 也一样。
- 事件堆太多会像音效轨，一段台词两三个够了。
- `[冷笑]` `[吸气]` `(gasp)` 属四词表外，**未实测，别当稳定能力用**。

实测（clone·带文稿，seed 42，台词 44 字，参考 13.4s）：括号内文字不被念出；`[叹气]` 生成 0.52s 呼气、`[笑]` 生成 1.4s 内 4–5 段轻笑；事件音量比正常说话低 15–20 dB；同句去掉括号 9.92s → 带括号 19.52s（事件本身约 1.9s，其余是事件前后的停顿，最长 2.2s 空档）。

**验语气事件别用 -38dB 静音检测**——叹气峰值只有 -35dB、均值 -42dB，常规静音门槛会把事件判成静音。要验就按「连续弱声段（-55～-30dB、时长 ≥0.3s、过零率偏高）」找，或者直接人耳听。

## 五、多角色对话（dialogue4，2–4 人）

一条命令吃一份 cast.json，一次出整段对话——2–4 个角色各说各的，轮间自动插静音，一个 mp3。**单人说话不进这里。**

```bash
node scripts/rhv.mjs dialogue4 --cast assets/casts/凡人修仙传三人.json --name 三人_三日 --out "<绝对目录>"
# 模板（全用 instruction 设计，不依赖音频，可直接跑）：assets/casts/模板-两人对话.json / 模板-四人对话.json
# 现成样例（克隆，2/3/4 人各一份，改台词即可）：assets/casts/凡人修仙传两人.json / 三人.json / 四人.json
# 旧名 dialogue 是别名，同一张图同一个执行器
```

cast.json 三段：`speakers`（**2–4 个**，`name / ref / ref_text / instruction / cfg`）、`script`（`[{"speaker","text"}]` 数组或"名字: 台词"字符串，原样喂 `#37`）、可选 `pause`（默认 0.3）与 `seed`。角色**既没有 ref 也没有 instruction** 会被拦（二选一必填）。

**2–4 人不用另建工作流。** 图 `2115846246844952578` 有 `#33–#36` 四个 Speaker 槽，但节点的 `speaker_1..4` 本身是 **optional 输入**，而且逐轮生成——源码里真正干活的只有 `used = set(turn_keys)`（剧本里开过口的角色）：参考音频编码 `for key in used`、生成 `for index,(name,line) in enumerate(turns)`。**没开口的槽既不编码参考音频，也不生成音频**，是**真零开销**，不是「少一点开销」。

所以少给角色时，脚本把多余的槽自动填成「占位角色」：名字唯一（`unused_slot_3/4`）+ 一条 instruction，`audio=none`。这样 `prepare` 阶段既不会撞 `Duplicate speaker name`，也不会撞 `no reference audio, so the instruction designs the voice`，而剧本不出现它 → 零额外耗时、零额外费用。日志会标出：

```
[rhv] dialogue4 · 2 角色（另 2 个占位槽不出场） / 6 轮 / 共 94 字（约 24s 语音）
  #33 阿箬  设计  指令 34 字  cfg=4
  #35 unused_slot_3  占位·不参与生成（不编码参考音频、不出音频）
```

**想静音某个角色，直接从剧本里删它的台词**，不用改演员表。

四条边界：

- **超过 4 人**要拆段（分几次跑再拼），或另建一张槽更多的图并在 `MODES.dialogue4.slots` 里登记——`BreezeTTS2MultiSpeaker` 的 `MAX_SPEAKERS` 就是 4。
- **少于 2 人直接拦下**，并打印单人的三条命令（`clone` / `design` / `director`）。
- **剧本里若出现占位名**会被拦下（`剧本里出现了占位角色：…`），那基本等于角色名写错了。
- `seed` 按**槽位**偏移（第 n 个槽用 `seed+n`）；而 **cast 里 speakers 的顺序就是槽位顺序**（第一个占 `#33`）。错开起点只是让两个角色不共用同一个随机数。顺序一换 `seed+slot` 就变，但**音色与语速都不由它决定**——音色来自各自的参考音频（或 `instruction`），节奏来自台词与指令。

**节奏与预算**：`pause` 0.3 是「聊得起来」的节奏，**正剧要 0.5**；台词越短（单轮 10–15 字）越要往上调，否则像连读。字数 ÷ 4.5 ≈ 秒（脚本打印的「约 X 秒」按 ÷4 估，偏保守）；单轮 15–20 字是舒适区，超过 30 字一轮就很难不被下一句打断。

**提交前预检**：脚本自动免费读一次图，核对四槽在不在、六个字段全不全、`auto_transcribe_if_empty` 默认值、输出节点 `format` 是不是 mp3；有一项不对就退出码 2、一分不花。确认是平台侧问题非要硬跑，加 `--no-preflight`（实测可行：三人 8 轮 28.87s，跳过预检照常出音频）。

**换 seed 重抽一版的边际成本基本只有生成本身**——上传命中缓存，不会重复传（见 §一）。

## 六、场景音（fx：音频 → 音频，全本地）

用户说「这段声音听着像电话里」「加点教堂混响」「变成对讲机」「让他在隔壁房间说话」——走这条。**不走平台、不扣币、断网也能跑**：混响和带通本来就是信号处理，DSP 给的是确定结果，同参数同输入逐字节可复现。

```bash
node scripts/rhv.mjs fx --list                                  # 看全部 28 个预设
node scripts/rhv.mjs fx --in 干声.flac --preset 电话听筒 --out ./场景音 --mp3
node scripts/rhv.mjs fx --in 干声.flac --preset 教堂 --mix 0.5   # 湿度覆盖
node scripts/rhv.mjs fx --in 干声.flac --preset 教堂 --dry-run    # 只打印滤镜链
```

两组预设：**空间 17 个**（教堂 / 穹顶 / 小教堂 / 礼堂 / 音乐厅 / 大音乐厅 / 小剧场 / 体育馆 / 隧道 / 矿洞 / 石室 / 史前墓室 / 石墓甬道 / 陵墓 / 厂房 / 巨型工业 / 户外），**通信音色 11 个**（电话听筒 / 电话另一头 / 免提 / 对讲机 / 老式电话 / 大喇叭 / 电视里传出 / 隔壁房间 / 内心独白 / 水下 / 恶魔）。中英文名都认（`教堂` = `church`）。

**输出目录默认是当前目录下的 `./fx-out`**，而命令习惯是先 `cd` 进技能目录——不给 `--out` 就会把产物落在技能目录里。一律显式给 `--out <绝对目录>`。`lufs` 相反，默认与源文件同目录（`--out` 可改）。

**产物规格**：`<原名>_<preset.id>.flac`（默认；`--mp3` 转 mp3、`--name` 改名），固定 **48 kHz / 立体声**——空间类要双声道才成立。**这一条会改变后面 `lufs` 的口径**：立体声自动取 -14.4，会把已对齐的 -17.4 再推 3 dB，链式处置见 `响度.md`。

**ffmpeg 能力**：空间类要 `afir`，通信类要 `acrusher` / `rubberband`（水下、恶魔用后者）。Windows 上 gyan.dev 的 full build 都有；报「处理完但没生成中间文件」时先确认：`ffmpeg -filters | grep -E "afir|acrusher|rubberband"`。

空间类靠 `assets/irs/` 里 17 条真实空间 IR（OpenAIR，CC BY 4.0，**对外交付要署名**，写法见 `assets/irs/IR来源与署名.md`），通信类靠滤波链、个别再叠一层房间。

**四条必须知道的（都实测过）**

1. **`afir` 的 `dry`/`wet` 是乘性增益，任一置 0 直接静音**（`dry=1:wet=0` 输出 -91 dB）。脚本固定 `dry=1:wet=10`，湿度用混音权重控制，别去调它自带的旋钮。
2. **`afir` 输出会被截断到干声长度**，混响尾巴必须靠 `apad` 预留。脚本按 `IR 长度 + 1s` 自动 pad，`--tail` 调小会切尾、听着"说完就断"。
3. **卷积本身衰减 40 dB 左右**，`irs.json` 里的 `makeup_db` 是逐条用粉噪实测的补偿值（+7 ~ +23 dB）。换 IR 或换 ffmpeg 版本必须重测，别手调。
4. **干湿交叉会让整体电平掉 4–6 dB**（湿声和干声不相干，叠加不等于相加）。脚本默认按输入响度线性补回来（保 TP ≤ -1 dB）；要"远、轻"的效果用 `--no-level`，要指定就 `--gain -6`。

**预设改不了发声方式（内心独白 / 气声类必读，2026-10-31 实测）**

现象：clone 干声 + `--preset 内心独白`，听完反馈「不像内心独白，像正常人说话」。

根因：`fx` 只改空间与频响（去混响、加低频、贴耳），**改不了怎么发声**。clone 出来的干声是出声朗读——胸腔共鸣、吐字饱满、送气足；把它塞进贴耳的空间，听感还是「站在旁边说话」。

配方三件事，缺一件就露馅：

1. **源头走 `director`，别在 clone 干声上硬套预设**。气声六维（六项全写，漏哪项漏哪项，原理见 `写法.md` §0）：
   > 音量压到极低，几乎只有气声，不催动胸腔；声带几乎不闭合振动，句尾的字散在气里，换气声可闻；语速比参考略快，句子连着推；情绪冷静盘算、无起伏；句号处几乎不停。
2. **再套 `--preset 内心独白`**。
3. **手动补增益**：预设把输出对齐到**输入响度**，气声本身轻，实测只出 -25.3 LUFS（同批其他场景音 -18.5），演示时会像没声音。按差值补到同批水平（这次 `-af volume=6.8dB` → -18.8 LUFS、峰值 -6.6 dB）。

验收别靠耳朵「感觉像」，看 `ffmpeg -af astats` 的 `Peak level / RMS level / Zero crossings rate`：

| 指标 | 出声朗读 | 气声独白 |
|---|---|---|
| 峰值 | -4.0 dB | -8.6 dB |
| RMS | -20.6 dB | -27.6 dB |
| 过零率 | 0.145 | 0.179 |

峰值与 RMS 掉 4–7 dB、过零率涨两成以上，才是真气声；只是滤镜变闷、三组数字没动，说明源头没改。台词照旧过一遍 `stt` 核字——气声容易糊。

**边界**：不做环境音床（下雨 / 风 / 森林 / 马路），也不做 Autotune（需要音高检测）；完整「不做」清单见 `SKILL.md` 边界一节。

## 七、同一个音色做系列 / 只改几个节点

`nodeInfoList` 只传要改的节点，没传的按工作流里存的值跑——"只改台词和指令两个节点"就是靠这个，不用重建工作流。

- **seed 就是一个随机数**：脚本默认随机生成并推 `#3`，给了就固定。它不控制音色，也不控制语速和停顿——音色由 `--voice` 描述（design）或参考音频（clone/director）决定，节奏由台词与指令决定。换 seed 只是换一条采样路径：实测同一段描述跑三个种子仍是同一个音色，字/秒的差异属采样抖动（三组数字见 `声线库.md` §六）。同 seed 也不保证复现（`实测数据.md` §五）。它实际只有一个用途：日志里留个号，复现问题时对得上。
- 做十条以上的系列（方言、多语种、角色台词集）：外层写 JSON 配置（id / 台词 / 指令）+ for 循环**串行**提交，单条失败重试一次后继续下一条，别并发（421 挡回来还浪费一次排队）。每条 append 进 `_voice.log.jsonl`，中途挂了也知道跑到第几条。
